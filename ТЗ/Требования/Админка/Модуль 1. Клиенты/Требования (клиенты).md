**Описание модуля:** 
1. Этот модуль предназначен для работы с клиентами: чтение, заведение, редактирование, удаление (CRUD).
2. Функциональные возможности относятся только к роли "Админ".

### **Функциональные требования**

#### **Требования 1. Отображение клиентов**
В "Модуль 1. Клиенты" отображаются только клиенты без отметки о удалении, то есть все клиенты, у которых в столбце "Дата удаления" таблицы Clients = NULL. 

##### **Требование 1.1:** Отображение клиентов на главной странице модуля

**Описание:** Система должна отображать список клиентов в виде таблицы с пагинацией.
**Поля таблицы:**
1. ID в системе
2. УНП 
3. Наименование клиента 
4. Телефон
5. Тип клиента (ФЛ, ЮЛ)
6. Доп. поле таблицы "Действия" , где будут кнопки "переход в карточку клиента", "редактировать клиента"

**Детали**: 
1. Система отображает число отобранных клиентов в таблицу (просто число, которое показывает сколько в таблице клиентов)
2. Сортировка по умолчанию "от новых к старым" по Дате создания клиента.
   (реализована сортировка по айди автоинкремента)

---

##### **Требование 1.2:** Фильтры для отображения списка клиентов

**Описание**: Система должна отображать клиентов по определенно выставленным фильтрам. 
В виде таблицы с пагинацией, заполненной списком клиентов, которые соответствуют фильтрам.

**Детали**: 
- Виды фильтров: 
1. УНП - пользователь вводит необходимое значение для поиска в текстовое поле. Фильтрация происходит таким образом, что отбирает всех клиентов, у которых в УНП есть хоть какая-то часть введенных символов в любом регистре (ILIKE SQL).

2. Наименование - пользователь вводит необходимое значение для поиска в текстовое поле. Фильтрация происходит таким образом, что отбирает всех клиентов, у которых в наименовании есть хоть какая-то часть введенных символов в любом регистре (ILIKE SQL).

- Другое: 
1. Применение фильтров происходит после нажатия на кнопку "применить".
2. При отображении отфильтрованного списка клиентов пагинация остается, той же которую настроил пользователь
3. Если фильтр не дал результатов, то в таблице появляется одно поле "Клиенты не найдены"
4. Должна быть кнопка "Сбросить фильтры". Кнопка работает без подтверждения. 
5. При сбросе фильтров установленная пользователем пагинация не сбрасывается.

**Сценарий 1.2.1:** Поиск клиентов по критериям: 
Предусловие: Пользователь находится на главной странице модуля работы с клиентами, где размещена таблица со всеми клиентами (1-я страница таблицы).
1. Пользователь вводит в фильтр "Наименование клиента" слово "перевозк"
2. Нажимает на кнопку "Применить"
3. Система ищет все возможные вхождения этого слова в названии клиентов (ILIKE).
4. Система отображает список клиентов (например, 47 клиентов).
5. Пользователь находясь на первой странице таблицы первоначально видит 20 отобранных по фильтру клиентов. (всего три страницы: 20 клиентов, 20 клиентов, 7 клиентов)
6. Пользователь проставляет максимальное отображение количества клиентов на одной странице равным 50 клиентам (настраивает пагинацию).
   При этом фильтр с наименованием до сих пор применен.
7. Нажимает на кнопку "Поиск"
8. Система отображает список из 47-ми клиентов на одной странице.

##### **Требование 1.3:** Настраиваемая пагинация списка просматриваемых клиентов
**Описание**: Система должна иметь возможность настраивать количество отображаемых клиентов на одной странице.
**Вид**: Выпадающий список с тремя пунктами: 20, 50 и 100.
**Расположение:** В блоке с фильтрами 
**Ограничения:** параметр пагинации передаётся в API, но ограничен значениями 20, 50, 100.


---

##### **Требования 1.4:** Просмотр карточки клиента

**Описание**: Система должна иметь возможность просмотра карточки клиента. 

**Отображаемые поля**: 
1. ИД клиента
2. Наименование клиента
3. УНП 
4. Тип клиента
5. Телефон
6. Дата регистрации клиента (формат ДД-ММ-ГГГГ)
7. Адрес клиента
8. Дата создания клиента
9. Последняя дата обновления клиента

Также, должны отображаться записи сделок из **"Модуль 2. Сделки"**, которые связаны с этим клиентом.
**Вид**: таблица со списком сделок с пагинацией.
**Отображаемые поля сделки**: 
1. ИД сделки 
2. Статус сделки 
3. Дата создания сделки 
4. Менеджер по сделке
5. Кредитный эксперт по сделке

**Детали:** 
1. Список сделок отсортирован по убыванию даты создания сделки (сначала новые)
2. Есть возможность отфильтровать сделки по: 
   2.1. ID сделки
   2.2. Менеджеру сделки (выпадающий список из таблицы сотрудников)
   2.3. Статусу сделки (Выпадающий список)
   2.4. Типу сделки (Выпадающий список)
   2.5. Фильтр по дате создания (Дата от, Дата до)
3. Настраиваемая пагинация (выпадающий список 20, 50, 100 записей сделок на одной странице)
4. Должна быть кнопка "Сбросить фильтры", которая убирает все установленные фильтры и отображает первую страницу таблицы всех клиентов.
   

**Дополнительно**: 
1. функция редактирования (Требование 2.2.) и удаления (Требование 2.3.) доступны из просмотра карточки клиента (находятся в шапке карточки клиента)
2. Функция создания лизинговой сделки доступна только из карточки клиента.

#### **Требования 2. Операции над клиентами**


##### **Требование 2.1: Создание клиента**

**Описание:** Система должна предоставлять форму для создания нового клиента.

**Детали:** 

- Поля формы:
1. УНП (обязательное поле)
2. Наименование клиента (необязательное)
3. Тип клиента (необязательное)
4. Дата регистрации (необязательное, формат ДД-ММ-ГГГГ)
5. Телефон (необязательное)
6. Адрес (необязательное)

- Другое: 
1. При незаполнении обязательного поля подсвечивать ошибку "Необходимо заполнить обязательные поля". При этом подсветить красным незаполненное поле.
 2. Невозможно создать клиента, если введенное УНП уже есть в базе данных. В таком случае необходимо вывести надпись "Клиент уже существует в системе".
 3. После успешного создания нового клиента происходит переадресация в карточку клиента

**Сценарий 1.4.1** Успешное создание клиента: 
1. Пользователь нажимает на кнопку создать клиента.
2. Заполняет УНП в поле формы для создания клиента
3. Нажимает на кнопку "Создать" в форме.
4. Система сохраняет клиента, переадресует в карточку клиента и показывает уведомление "клиент успешно создан"
   Уведомление в виде простой надписи сверху над основной информацией в карточке клиента (flash message).

---

##### **Требования 2.2:** Редактирование клиента

**Описание**: Система должна иметь возможность редактирования карточки клиента.

**Детали**:
- Форма редактирования:
1. Наименование клиента
2. Тип клиента
3. Дата регистрации
4. Телефон
5. Адрес

- Другое
1. Автоматически обновляется поле "Дата обновления", после успешного обновления информации о клиенте.

---

##### **Требования 2.3:** Удаление клиента (soft delete)

**Описание**: Система должна иметь возможность удалить клиента из отображаемой таблицы клиентов. 

**Детали**: 
1. Удаление происходит путем проставления даты удаления в базе данных записи о клиенте.
2. После нажатия на кнопку удалить система запрашивает подтверждение от пользователя модальным окном: "Удалить клиента?" - Кнопки:  "Да", "Нет".
3. Да - flash уведомление "Клиент удален"
4. Нет - отмена операции (ничего не происходит)

Ограничения: 
1. Нельзя удалить клиента, если за ним закреплены сделки в любом статусе.


#### **Требования 3**: Дополнительные функции модуля

##### **Требование 3.1:** Выгрузка списка клиентов в excel.

**Описание:** 
Система должна иметь возможность выгружать список клиентов в электронную таблицу excel.

**Детали:**
- формат файла: .xlsx
- Выгружаются все колонки базы данных
- Выгружаются только видимые данные с учетом фильтров (без учета пагинации)

При нажатии на кнопку "Выгрузить" система формирует список отображаемых клиентов в электронную таблицу Excel.
Если пользователь настроил фильтры отображения клиентов, то записи по клиентам выгружаются с учетом этих фильтров.

1. Защита от SQL инъекций во всех функциях модуля
