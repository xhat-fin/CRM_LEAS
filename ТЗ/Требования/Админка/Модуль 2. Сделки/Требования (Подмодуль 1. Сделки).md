**Описание подмодуля:**
Модуль предназначен для работы с лизинговыми сделками: отображение, создание, редактирование, удаление.

#### **Требования 1:** Отображение лизинговых сделок

**Описание:**
В "Модуль 2. Сделки" отображаются только сделки без отметки о удаление, то есть все сделки у которых дата удаления в таблице "Deals" = NULL.

##### **Требование 1.1:** отображение сделок на главной странице модуля

**Описание:**
Система должна отображать список сделок в виде таблицы с пагинацией
Поля таблицы: 
1. ID сделки
2. УНП клиента
3. Наименование клиента
4. Предмет лизинга
5. Менеджер
6. Статус
7. Сумма
8. Дата создания
9. Действия

**Детали:**
1. Система отображает общее количество сделок. (небольшая отметка о том, сколько сделок отображено в таблице модуля)
2. Сортировка по умолчанию от новых к старым сделкам.
3. В колонке действия на каждой строке сделки размещаются функциональные кнопки: просмотреть карточку клиента, редактировать, удалить (soft delete).


##### **Требование 1.2:** Фильтры для отображения списка клиентов

**Описание:**
Система должна предоставлять функцию фильтрации списка отображаемых сделок.

**Детали:**
1. Фильтр по "Менеджер" - выпадающий список, где отображаются пользователи из таблицы Users с ролью "manager"
2. Фильтр по "Кредитный эксперт" - выпадающий список, где отображаются пользователи из таблицы Users с ролью "expert"
3. Фильтр по "Оформитель" - выпадающий список, где отображаются пользователи из таблицы Users с ролью "accounter"
4. Фильтр по "Наименованию клиента" - текстовое поле для ввода значения.
   Пользователь вводит необходимое значение для поиска в текстовое поле. Фильтрация происходит таким образом, что отбирает все сделки, которые закреплены за клиентом, подходящие под введенный фильтр, то есть хоть какая-то часть введенных символов в любом регистре (ILIKE SQL).
5. Фильтр по "Статус" - выпадающий список из справочника статусов сделок (Модуль 4. Конфигурация - Справочник 8)
6. Фильтр по "Вид сделки" - выпадающий список из справочника типа сделки (Модуль 4. Конфигурация - Справочник 3)
7. Фильтр по "Дата от" - шаблонное поле для даты без времени в формате "дд.мм.гггг". Фильтрация происходит таким образом: все сделки, у которых **дата создания** от введенной даты в этот фильтр включительно попадают в таблицу отображаемых сделок. Сделки, созданные до введенной даты не входят в отображаемый список.
8. Фильтр по "Дата до" - шаблонное поле для даты без времени в формате "дд.мм.гггг". Фильтрация происходит таким образом: все сделки, у которых дата создания до введенной даты в этот фильтр включительно попадают в таблицу отображаемых сделок. 
   Сделки, созданные после введенной даты не входят в отображаемый список.

**Другое:** 
1. Применение фильтров происходит после нажатия на кнопку "Применить".
2. При отображении отфильтрованного списка сделок пагинация остается той же, которую настроил пользователь.
3. Если фильтр не дал результатов, то в таблице появляется надпись "Сделки не найдены"
4. Должна быть кнопка "Сбросить фильтры". Кнопка работает без подтверждения. 
5. При сбросе фильтров установленная пользователем пагинация не сбрасывается.

**Сценарий 1.2.1:** Поиск сделок по критериям: 
Предусловие: Пользователь находится на главной странице модуля работы со сделками, где размещена таблица со всеми сделками (1-я страница таблицы).
1. Пользователь вводит в фильтра "Название клиента" "перевозк" 
2. Нажимает на кнопку "Применить"
3. Система ищет все возможные вхождения этого слова в названии клиентов (ILIKE).
4. Система отображает список сделок (например, 47 сделок).
5. Пользователь находясь на первой странице таблицы первоначально видит 20 отобранных по фильтру сделок. (всего три страницы: 20 сделок, 20 сделок, 7 сделок)
6. Пользователь проставляет максимальное отображение количества сделок на одной странице равным 50 сделкам (настраивает пагинацию).
   При этом фильтр с наименованием до сих пор применен.
7. Нажимает на кнопку "Применить"
8. Система отображает список из 47-ми сделок на одной странице.

#### **Требования 4:** Логика системы

##### **Требование 4.1:** Автоматическое заполнение полей базы данных системой

**Описание:** здесь будет описано как и когда происходит автоматическое заполнение полей в базе данных.

**Детали**:
1. ИД менеджера (сотрудника, который создал сделку) заполняется автоматически из данных сессии пользователя, который создал запись сделки
2. ИД клиента берется автоматически из карточки клиента, так как функция создания сделки возможна только из карточки клиента
3. **Дата передачи** - автоматически проставляется системой в том случае, когда сделка передается на начальника кредитных экспертов (роль админ) для того, чтобы распределить сделку на конкретного кредитного эксперта.
4. Дата передачи в работу на КЭ - проставляется автоматически системой в тот момент, когда начальник кредитных экспертов распределяет сделку на конкретного кредитного эксперта:
   Начальник кредитных экспертов в специальном модуле будет распределять сделки и выбирать кредитного эксперта через выпадающий список. После проставления кредитного эксперта по сделке подтягивается его ИД.
5. Срок стоп листа. 
   В тот момент когда кредитный эксперт проставляет статус сделки "В стоп-листе" система начинает считать сколько рабочих часов сделка провела в этом статусе.
   Заполняется автоматически.
6. Дата создания - проставляется автоматически при создании сделки менеджером
7. Дата обновления - проставляется автоматически при каждом изменении записи в базе данных
8. Дата удаления - проставляется при soft delete.
